## Checked and holding (this round)

- **Thumbnail URL lifetime:** only one `GalleryList` is mounted at a time. A mount and an unmount in either order are safe. A refresh still in flight when the last list unmounts leaks at most one listing's URLs, until the next refresh's stale path revokes them.
- **Notice lifecycle:** a stale failure pushes nothing, and only the newest listing can push or dismiss. Dismissing an id the Editor already dismissed is harmless.
- **Focus return:** a connected opener still gets focus back (`Dialog.vue:53-56`). Only one Delete dialog shows at a time, because the standby one stands down while `listsMounted > 0`.
- **Sort and eviction:** NaN, missing, `null`, strings and ±1e17 all sort as the oldest, regardless of input order. The count still includes damaged entries.
- **Conventions:** no new CSS and no cross-feature imports. Notices still go only through `useNotices`, and errors still flow as `Result`/`AppError`.
- **End-to-end trace:**
  - Each user story in spec §4 (US-01 to US-07) is still covered.
  - Each acceptance criterion in §5 (AC-01 to AC-21) still reaches at least one task in `tasks.json`, plus code and a test.
  - No AC carries `added-by-fix`.
  - T50–T55 are `done` in `tracker.md`, and the test-plan rows match the tests.
- **Below threshold, not raised:**
  - Esc during a reopen, followed by a release, mutates a replaced entry object. `damagedIds` still records the mark.
  - A refresh already running could in theory put a deleted entry back during `confirmDelete`'s `nextTick`. Nothing starts a refresh while the modal is up.
